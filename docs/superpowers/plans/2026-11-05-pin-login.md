# PIN Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users sign in to the local desktop app with a 4-digit PIN, shared with staff switch and manager approvals, with a hard 5-failure lockout.

**Architecture:** The existing staff PIN (`users.staff_pin_hash`) shrinks to 4 digits and gains a persistent failure counter. Two new tRPC procedures (`auth.pinLoginCandidates`, `auth.pinLogin`) are gated by a per-boot secret that only Electron main knows and injects through the in-process `app.inject` transport, so Hub/web clients can never reach them. The web login page offers a PIN mode when the desktop bridge exposes it.

**Tech Stack:** Fastify + tRPC + Drizzle/SQLite (server), Electron main/preload (desktop), React + i18next (web), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-pin-login-design.md`

## Global Constraints

- PIN: exactly 4 digits, `/^\d{4}$/`. Hash domain `puntovivo:staff-pin:v2:`. Dummy PIN `'0000'`.
- `PIN_LOCKOUT_THRESHOLD = 5` consecutive failures, shared across PIN login, staff switch and manager approvals.
- PIN sessions use `createStaffPinSessionClaims()` (`authMethod: 'staff_pin'`, 8h cap via `STAFF_PIN_SESSION_TTL_MS`).
- PIN login is never reachable over real HTTP; error code `AUTH_PIN_LOGIN_UNAVAILABLE`.
- Locked PIN error code `AUTH_PIN_LOCKED`; wrong PIN keeps the existing `AUTH_STAFF_PIN_INVALID`.
- Local capability header: `x-puntovivo-local-auth`, compared with `crypto.timingSafeEqual`.
- Artifacts (code, comments, docs, commits) in English; UI copy in both `en` and `es` locales.
- Conventional commits, no AI attribution lines.

## Review Focus

- Locked user who then logs in with password: counter resets and PIN works again (Task 2 test `resets failures on password login`).
- Wrong PIN against a user with no PIN / inactive user / other tenant: same error and same Argon2 cost as a wrong PIN (Task 4 test `pinLogin treats unknown, inactive and unenrolled users as invalid`).
- Request to `auth.pinLogin` with a forged or empty `x-puntovivo-local-auth` header: refused (Task 3 test `rejects wrong and missing capability`).
- Desktop running as Hub client: renderer reports PIN login unavailable and the login page shows password only (Task 6 test `hub mode does not expose pin login`, Task 7 test `falls back to password when pin login unavailable`).
- User types a 6-digit PIN from before the migration: rejected by input validation, UI only accepts 4 digits (Task 8 tests in `StaffPinModal.test.tsx` and `StaffSwitchModal.test.tsx`).

  - `failures are shared between switchStaff and manager approvals`: 3 wrong via switch + 2 wrong via approval decision → correct PIN via switch fails `AUTH_PIN_LOCKED`.
  - `successful PIN resets the counter`: 4 wrong, 1 right, 4 wrong → still succeeds.
